# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is a STRUCTURAL REFACTOR of `components/layout/sidebar.tsx`, not a restyle. Every token, class, and interaction pattern below is lifted verbatim from the existing sidebar and Command Center — nothing new is invented. Where a new element is unavoidable (filter input, group headers, chevrons), it reuses existing tokens/components at their existing sizes.

## Spacing Scale

Declared values (must be multiples of 4) — these are the values **already in use** in `sidebar.tsx` and preserved exactly:

| Token | Value | Usage (existing, preserved) |
|-------|-------|-------|
| xs | 4px | `space-y-1` between nav items; `gap-1` inside filter icon |
| sm | 8px | group header vertical padding; gap between chevron and label |
| md | 16px | `p-4` nav container padding; `p-4` footer padding; `px-4` button/header padding; `gap-3` icon-to-label gap (12px, still on-scale) |
| lg | 24px | `p-6` logo header padding |
| — | 44px | filter input row min touch target height (accessibility minimum for the search box, applied via padding not a new token) |

Exceptions:
- `py-2.5` (10px vertical) on nav item buttons is **pre-existing** in `sidebar.tsx` and is NOT a multiple of 4. It is preserved as-is because this phase changes structure, not pixel-level button geometry — do not "fix" it to `py-2` or `py-3`, that would visibly shift every nav row.
- New group-header rows use `py-2` (8px, on-scale) — they are new elements, so they follow the clean 8-point scale rather than inheriting the pre-existing 10px quirk.

### Collapse/expand behavior (SIDE-04)

- Each category group is a `Collapsible` (shadcn, once added) with a header row: chevron icon (`ChevronRight`, rotates 90° to `ChevronDown` state via `data-state=open` — reuse lucide `ChevronRight` + CSS rotation rather than swapping icons, consistent with base-ui Collapsible's own state attribute) + category label (12px/500/uppercase/`tracking-wide`, `text-sidebar-foreground/60`) + no count badge (keep header minimal, matches existing sidebar's unadorned style).
- **On load:** the group containing the current active route (`pathname` match, same logic already in `sidebar.tsx`) starts expanded. All other groups start collapsed. If the active route is "Overview" (pinned, ungrouped), no group needs to auto-expand — none is more "active" than another, so all groups start collapsed in that case.
- Expand/collapse state is local component state (`useState`), not persisted — matches the phase's scope (no new persistence layer requested).
- Multiple groups may be expanded simultaneously (accordion-all, not accordion-single) — with only 6 groups this doesn't create clutter, and single-expand would fight the filter behavior below.

### Filter/search behavior (SIDE-02)

- One `Input` (shadcn, existing component, reused as-is at its default `h-8` sizing) placed directly below the logo header, above the pinned "Overview" item and the category groups. Wrapped in a `relative` container with a `Search` (lucide, `size-3.5`, `text-sidebar-foreground/40`) icon absolutely positioned at `left-2.5`, input gets `pl-8` to clear it — standard shadcn search-input pattern, no new component needed.
- Filtering is case-insensitive substring match against `item.name` only (not `href`) — client-side, no debounce needed at 22 items.
- While a non-empty filter is active: every group containing at least one match auto-expands (overriding the on-load active-route expansion); groups with zero matches are hidden entirely (not shown collapsed-empty); the pinned "Overview" item is hidden if it doesn't match the filter text too (it's just another filterable name, not exempt).
- If the filter matches nothing: render the Empty State copy (`No matches` / `Try a different search term.`) in place of the group list, styled as `text-sm text-sidebar-foreground/60` centered in the nav area, `py-8`.
- Clearing the filter (empty string) restores the on-load expand state (active route's group open, others collapsed) — do not leave whatever expand state the filter produced.

### Overflow / usability at 20+ entries (SIDE-05)

- **Required structural addition:** the `<nav>` element currently has no scroll handling (`flex-1 p-4 space-y-1`, no `overflow-y-auto`). With 6 group headers + up to 22 items, expanded content can exceed viewport height. Add `overflow-y-auto` to the nav container (structural fix, not a visual restyle) so the sidebar scrolls independently of the page while the logo header, filter box, and footer (Sign out/Settings) stay fixed in place (`shrink-0` on header/footer, unchanged from current layout).
- Sidebar width stays `w-64` (256px) — unchanged. No responsive collapse-to-icon-rail behavior is in scope for this phase (not requested in SIDE-01..05).

### Active-item styling (unchanged, preserved exactly)

Reuse the existing conditional classes verbatim for whichever item is active within its group:
```
bg-sidebar-primary/10 text-sidebar-primary border border-sidebar-primary/30   (active)
text-sidebar-foreground hover:bg-sidebar-primary/5                            (inactive)
```
Including the trailing `w-1.5 h-1.5 bg-sidebar-primary rounded-full` active-route dot. Do not restyle nav item rows — only their container (grouped instead of flat) changes.
